# DDR3 Controller VP — Agreed Limitations

Audience: firmware developers, platform integrators and reviewers. This file lists every place where the VP knowingly differs from the HAS/MAS hardware description, or deliberately does not model something. The [traceability matrix](traceability.md) points here (status `Limitation`) for each affected requirement.

Requirements classed ABSTRACTED in the audits (pin-level handshakes, internal pipelines) carry status `n/a`. They are covered by L-01 and L-02.

Firmware-visible field encodings that the specification leaves undefined are a separate topic: they are **provisional**, not limited. See L-14.

| ID | Limitation | Consequence for firmware / integration | Requirements |
|---|---|---|---|
| L-01 | **Transaction level.** One TLM call is one complete AXI transaction. AW/W/AR/B/R VALID/READY handshakes, owed W beats, CDC FIFOs, SYNC_STAGES latency, metastability and clock gating of port domains are not modelled. | A quiesce takes effect between transactions, never between beats. Early/missing WLAST cannot be expressed. Signal-level AXI/DFI protocol checks need RTL simulation. | FE-2.2-10, FE-6.1.2-01, FE-6.1.6-05, CSR-8.1-37, all ABSTRACTED FE rows |
| L-02 | **Approximate timing (DEC-02).** Per-bank open-row model with tRCD/tRP/tRAS/tRRD/tFAW/tCCD/CL/CWL/AL/tWTR/tRTW/tRTRS and tRFC refresh windows. Requests are served in install order. There is no out-of-order scheduler, no write-drain hysteresis, no QoS arbitration, no aging and no reserved-rate shaping. | Latency is plausible but not cycle-exact. Bandwidth figures are not claimed. ECC traffic whose companion granule shares a bank with the data shows row conflicts that a reordering scheduler would hide. | FE-2.2-19, FE-6.1.10-05, FE-6.1.11-01, BE-6.2.9-01 |
| L-03 | **Capacity counters.** The VP models 32 transaction contexts per port and 16 backend request slots. It does not model the 32-slot write store, the 16 return slots, the ingress FIFO depth or the per-context atom window as separate limits. | No functional effect; only back-pressure timing differs. | FE-6.1.7-01, FE-6.1.8-02, FE-6.1.5-05 |
| L-04 | **Scheduler and occupancy status words read 0** (DEC-03): SCHED_STATUS, STAGED_WRITE_OCC, WAIT_OLDEST_*, DISPATCH_STATUS, READ_META_STATUS and BACKEND_OCCUPANCY0/1. SERVICE_COUNT_* count real accepted atoms. | Firmware must not depend on these words. | BE-6.2.9-02 |
| L-05 | **Maintenance arbitration.** Lifecycle actions are serialized by the command mutex, the drain rules and the power/training gates. The 5-level maintenance priority and rotation are not modelled. Refresh is lazy: a "rejected refresh proposal" does not exist. A mandatory refresh urgency does not block issue to its rank by itself; REF windows do delay it by tRFC. | Refresh debt, urgency, saturation and IRQ_RAW[5] behave as specified. Issue blocking under mandatory urgency appears only through REF windows. | LC-9.1-02, LC-9.2-03, LC-9.2-07 |
| L-06 | **Power exit timing** (tXP/tXPDLL, tCKSRX + tXSDLL + ZQ) is applied to the P-channel transition. It is not applied again to the first RD/WR after the wake. | Wake latency is accounted once, at the transition. | BE-6.2.7-09 |
| L-07 | **Unreachable backstops.** Row overflow (DECERR poison), companion range fault and impossible geometry (SLVERR + IRQ_RAW[4]) are implemented and unit-tested, but legal TOPO_COMMIT images cannot reach them. Request-slot reuse while a return is pending is impossible by construction, so the stale-generation event is reachable only through injection. | None for legal configurations. | BE-6.2.2-11, BE-6.2.2-12, BE-6.2.4-03 |
| L-08 | **No timeouts on reset requests or quiesce.** Neither document gives a value for a reset-request acknowledgement timeout (GAP-LC-14). A port or global quiesce waits indefinitely (HAS FE10). | The platform reset controller and firmware must apply their own watchdogs. | LC-7.1-06, FE-6.1.14-07 |
| L-09 | **One time base.** All domains share the SystemC kernel time. The `aclk ≤ 2 × clk` integration rule has no meaning in the VP and is not checked. | None. | LC-7.1-08 |
| L-10 | **Same-cycle CSR accesses.** HAS says a read and a write that hit one register in the same cycle see the pre-write value. In the VP, two masters at the same simulated time are ordered by process scheduling. Each access returns one controller cycle after it is decided (VPL-05). | Do not rely on same-time ordering between two CSR masters. | CSR-8.2-10 |
| L-11 | **Status without CSR bits.** HAS names mission-gate levels (training-ready, scrub-complete, power-allowed, recovery-required) and scrub progress/busy, but gives no register field for them (GAP-CSR-20, GAP-BE-19). The VP publishes mission_ready, init_complete, global_idle, fe_drained and irq as pins, which DDR_SYSCTRL mirrors (DEC-04). The rest are available as host getters (`scrub_progress()`, `scrub_complete()` …) and through INIT_STATUS / POWER_STATUS. | Firmware detects readiness through DDR_SYSCTRL STATUS or INIT_STATUS[15] (admission blocked) after a snapshot. | LC-9.4-03, BE-6.2.20-11 |
| L-12 | **Build options not modelled.** Live DFI update (CAP_FEATURE[9] = 0; update observations are tied off), the topology-mismatch duplicate check (FATAL_STATUS[5], PDENY while it is set) and the write-fetch watchdog (FATAL_STATUS[4]) are absent, as in the MAS default build. | The corresponding bits never set. | IF-1.5-12, LC-9.3-08 |
| L-13 | **Storage and addressing.** Data is stored by physical granule index, so a geometry change does not scramble contents (BE-6.2.2-19). Regions are normalized to user offset 0, so regions of one port, and of different ports, alias each other (SOQ-20). DRAM contents survive every reset; this retention is not promised to firmware. | After a TOPO_COMMIT, treat memory as undefined (with ECC the startup scrub zeroes it). Map regions knowing that they alias. | BE-6.2.2-19, FE-6.1.3-03, LC-7.1-07 |
| L-14 | **Provisional encodings (DEC-13).** Every field encoding that neither HAS nor MAS defines comes from the proposals in [spec_owner_questions.md](spec_owner_questions.md) Part A and lives in `include/fx1_ddr3/provisional_encodings.h`: INIT stage/error codes, TRAIN_CMD/STATUS, POWER_ERROR, PSTATE codes, PHY_BRIDGE_ERROR, ECC_LAST_INFO, quarantine token kinds, FATAL_STATUS[2:0], blocker codes 0xE0–0xE6, FE_PORT_CMD op 2, refresh urgency/status bits, PHY_STATUS packing, QoS class codes and SERVICE_COUNT class membership. | Firmware must use the macros, never the numbers. These values change when the specification is completed. | SOQ-01..14, SOQ-36 |
| L-15 | **QoS sideband (SPEC-04).** No QoS CSR exists (HAS). The platform programs the per-port class table and the reserved-rate values through the sideband (DDR_SYSCTRL in FX1). The class is captured at acceptance and counted in SERVICE_COUNT_*, but does not change service order. The reserved rate is stored only (GAP-FE-23). A port admits nothing until its table is marked configured (FE05). | Boot firmware or the platform must configure each used port's QoS table before traffic, and again after a port soft reset. | FE-6.1.10-05/06, FE-6.1.11-01, FE-6.1.11-02 |
| L-16 | **Fault-injection reach.** Read-return faults target the first granule read of AXI read transactions, not the internal reads of ECC writes. DFI write-result faults are per granule write. Pin-level PHY faults are expressed through the functional PHY provider. | The fault catalogue lists what can be injected. | — |
| L-17 | **Exclusive access** follows the HAS 32-byte granule (not the MAS 128-byte window). An exclusive access spanning more than one granule never succeeds (SOQ-22). Reservations follow normalized addresses, so they alias like the data (L-13). | Use naturally aligned exclusive accesses of at most 32 bytes. | FE-6.1.12-01, GAP-FE-03 |
| L-18 | **DRAM command acceptance.** MRS, ZQCL, REF, PREA and power commands are not sent over a DFI command channel. Their timing is applied as waits gated by the PHY `timing_wait_ok` level. | Initialization stage timing is controlled by the INIT_* words and the PHY levels only. | LC-9.1.1-04 |
| L-19 | **CPU speed on the FX1 VP.** The VP harts have no cache (CDC-VP policy: all CPU traffic crosses TLM), and the FX1 bus serializes all `MEMCTL_DDR` traffic in FIFO order. With the DDR3 controller every fetch costs about 36 ns (19 ns with the former RAM), and a fetch queued behind a DMA burst waits for it: about 2× slower CPU in simulated time in general, up to 9× during ISP streaming. Host time rises about 4–5× (SystemC process switches per access). | Software timing on the VP is pessimistic compared with silicon, where the CPU runs from its caches. Do not calibrate CPU-versus-DMA races or console pacing on the VP; tests that did were adjusted (VPL-49). | — |
| L-20 | **DDR_SYSCTRL is a VP placeholder** (DEC-04): its address, register map, reset pulse width (100 ns), reset-safe limit (1 ms), automatic-wake policy and its retry back-off (1 µs doubling to 1 ms) are not FX1 silicon. | Firmware that uses it is VP-specific; isolate it behind a platform layer. | — |
| L-21 | **Host address convention.** `--dump`, `--load` and the `ce`/`ue`/`check` faults convert a global address to the user offset `address − 0x8000_0000`, which is the bootstrap map and any region 0 that firmware commits at that base. A region map at another base moves the data, not the conversion. | Dump/inject with the bootstrap map or a region 0 based at 0x8000_0000. | — |

## Verification limits of this delivery

- Sanitizer runs (ASan/UBSan) were not possible on the delivery host: libasan and libubsan are not installed. `make sanitize` is ready for a host that has them.
- CPU/firmware acceptance on `fx1_soc` is reported in [acceptance_report.md](acceptance_report.md); its limits are L-19 to L-21.
